一、项目是什么 — 不是代码，是一份"课程"

LLM Infer Journey 是一个 文档驱动型学习项目，而非可运行的软件仓库。

它是一份详尽的 30 天转行课程：帮助一位拥有 7 年 Intel ISP/IPU 系统软件经验的工程师， 转型为国内头部大模型公司的 LLM 推理工程师（目标公司：字节 AML、Moonshot、DeepSeek、MiniMax 等）。

产出目标：3 个 GitHub 项目 + 4 篇技术博客 + 1 个 vLLM 开源 PR + 一个本地 Coding Agent 部署。

关键认知：这个仓库里没有 src/、tests/、pyproject.toml 或 Makefile。 所有代码产出都在 30 天学习过程中逐步创建。

五、AI 教练模式 — COACH.md

这个项目为 AI 助手定义了严格的 教练 + 助教 角色，而不是代写工具。

4 级介入深度

级别AI 做什么使用场景
L1只给提示和方向做新东西时（默认）
L2给伪代码 + 用户实现理解到位后的编码（推荐默认）
L3给完整代码 + 用户逐行 review用户说"直接看代码"
L4AI 写完全部代码仅限用户说"直接写"或"赶时间"

7 条铁律（摘要）

  1. 先问"想学什么" — 反问 3 件事：学习目标 / 当前理解 / 介入深度
  2. 默认 L1-L2 — 不主动写完整代码
  3. 先 Why 再 How — 不直接丢代码
  4. 费曼技巧 — 每 checkpoint 出 2-3 道口试题反向验证
  5. 类比已有知识 — warp SIMD ≈ NEON，PagedAttention ≈ MMU 页表
  6. 诚实标注知识边界 — 2025 H2 后内容必须 WebFetch 查最新
  7. 会话结束更新 progress.md — 主动提议，用户同意才写

每日固定流程

  1. 读当日面试题 → 明确要掌握的概念
  2. 读参考代码 → ~/3rd/vllm 或 ~/3rd/nano-vllm
  3. 回答面试题 → 用户用自己的话答，AI 纠正
  4. 手工作业 → 理解到位后才 coding
  5. 费曼检查 → AI 出 2-3 道口试题
  6. 写每日笔记 → ≤30 行写入 progress.md

七、每日学习流程

每天严格按照以下顺序执行，不要让理解没到位的用户写代码：

  1. 读 progress.md 最新条目 → 确认今天是 Day 几、上次进度
  2. 打开当天 day-N.md → 先看 🎯 今日面试题
  3. 用户用自己的话回答面试题 → AI 纠正/追问
  4. 读参考代码 → 去 ~/3rd/vllm 或 ~/3rd/nano-vllm 找对应实现
  5. 动手 coding/experiment → 按 L1-L4 模式由 AI 辅助

// vec_add.cu
__global__ void vec_add(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];
}
// 关键学习：Grid/Block/Thread 三层结构、cudaMalloc/CudaMemcpy/cudaFree
// warp = 32 线程同步执行

八、本地 Coding Agent 部署

目标：用本地 RTX PRO 6000 + Qwen3.6-27B-FP8 跑 OpenCode / Cursor / Continue，替代 GitHub Copilot。

一键启动脚本

# 保存为 ~/serve-coding.sh
#!/usr/bin/env bash
set -e
exec vllm serve /home/xuefeiz2/models/Qwen3.6-27B-FP8 \
    --host 0.0.0.0 --port 8000 \
    --max-model-len 262144 \
    --gpu-memory-utilization 0.92 \
    --kv-cache-dtype fp8 \
    --enable-prefix-caching \
    --prefix-caching-hash-algo builtin \
    --enable-chunked-prefill \
    --max-num-seqs 8 \
    --enable-auto-tool-choice \
    --tool-call-parser hermes \
    --served-model-name local-coder \
    2>&1 | tee $HOME/logs/vllm/$(date +%Y%m%d-%H%M%S).log

十二、风险与注意事项

⚠️ 系统内存偏紧

当前 ~30GB DDR5。加载 27B 模型时 host 端峰值 ≈ 27GB，Week 4 mini-vLLM 测 batch>16 会 OOM。建议 Week 1 前升级到 64GB+。

⚠️ Blackwell sm_120 兼容性

vLLM quant 表中 sm_120 尚无独立列。FP8 W8A8 / NVFP4 实际能否跑、性能多少 → 需 Week 3 Day 17-18 自验。sm_120 走 mma.sync + WGMMA，与 sm_100 的 tcgen05/TMEM 不同。

⚠️ 绝对不要碰 vLLM 进程

本机所有 agent（Claude Code、Codex、Pi 等）全部依赖同一套 vLLM 部署作为 LLM 后端。禁止 start/stop/restart/kill 任何 vLLM 进程。

AI 助手行为约束

  • AI 不主动 commit/push，除非用户明确要求
  • AI 不动计划文档（01-09 系列、README.md、COACH.md、AGENTS.md）
  • AI 不编造论文标题、arxiv 编号、API 名称、性能数据
  • AI 不引入计划之外的新技术
  • AI 必须 WebFetch 查 2025 H2+ 内容（vLLM v0.20+ / FA4 / NVFP4）
